## 一、项目背景与目标

### 1.1 背景

OpenHuman 桌面端的记忆系统（存储、检索、知识图谱、同步、联邦学习）原先深度耦合在主仓库 `src/openhuman/memory/` 中，无法独立复用。随着产品向多端（桌面 + 移动 + 服务端）演进，记忆系统需要：

- 作为独立库被第三方 Rust 项目引用
- 以 HTTP 微服务形式部署到云端或边缘节点
- 通过 Python 绑定供数据科学和自动化脚本使用
- 通过 WASM 在浏览器端提供离线计算能力

### 1.2 目标

将记忆系统从主仓库完整抽取为 **6 个独立 crate**，实现：

1. 零耦合：不依赖主仓库任何模块即可编译运行
2. 全能力：覆盖存储、检索、图谱、同步、联邦学习全链路
3. 多形态：Rust 库 / HTTP 服务 / Python 包 / WASM 模块 四种接入方式
4. 生产就绪：612 个单元测试 + 集成测试全部通过

## 四、核心能力详解

### 4.1 知识图谱

| 能力 | 说明 | 技术方案 |
|------|------|----------|
| 持久化存储 | 节点 + 类型化边 + 权重 + 证据引用 | SQLite 邻接表 |
| 自动关系发现 | 从 chunk 中提取共现、时序、主谓宾关系 | 规则引擎 + 可选 LLM |
| 图嵌入 | 每个节点生成语义向量，支持最近邻搜索 | TransE（自研轻量版） |
| 时序分析 | 关系演化追踪、热度衰减、时间窗口查询 | 指数衰减 + 半衰期模型 |
| 可视化导出 | 支持 Graphviz DOT 和 JSON 格式 | 全图导出 |

### 4.2 多设备同步

| 能力 | 说明 | 技术方案 |
|------|------|----------|
| 变更追踪 | 每次写入生成 Lamport 时间戳的 ChangeEntry | Lamport 逻辑时钟 |
| 设备身份 | 每设备 X25519 密钥对 + 唯一 device_id | x25519-dalek |
| 对端发现 | 局域网 mDNS 广播 + 云端 relay 注册 | `_openhuman-memory._tcp` |
| 数据传输 | 可插拔传输层：LAN / Relay / Direct | async trait |
| 冲突解决 | 按数据类型自动选择策略，不可解决的存入冲突表 | LWW / Union / Idempotent |
| 端到端加密 | 传输内容全程加密，中继不可读 | XChaCha20-Poly1305 + HKDF |

### 4.3 联邦学习

| 能力 | 说明 | 技术方案 |
|------|------|----------|
| 模式提取 | 从用户记忆中发现时序、偏好、知识模式 | Sigmoid 置信度评分 |
| 隐私保护 | 频率加噪、PII 泛化、预算管控 | ε-差分隐私 (Laplace) |
| 安全聚合 | 服务端只能看到聚合结果，无法还原个体 | 加法秘密共享 |
| 群体智慧 | 聚合后生成分群模式，加速新用户冷启动 | 用户分群 + Top-K 推荐 |
| 合规审计 | 贡献可追溯、一键退出、GDPR 擦除 | SQLite 审计表 |

## 七、技术选型

| 维度 | 选择 | 原因 |
|------|------|------|
| 存储引擎 | SQLite (rusqlite) | 零部署、嵌入式、已在技术栈中 |
| 图存储 | SQLite 邻接表 | 需持久化，避免引入新依赖 |
| 图嵌入 | 自研 TransE | 纯 Rust、无 Python 依赖、轻量 |
| 加密 | chacha20poly1305 + x25519-dalek | RustCrypto 审计、常量时间 |
| 差分隐私 | 自研 Laplace | 轻量级，不需 tensor 框架 |
| 秘密共享 | 加法秘密共享 | 实现简单，满足聚合需求 |
| 冲突解决 | 自研 LWW + Union | 记忆数据模型简单，无需通用 CRDT |
| 设备发现 | mDNS (类型定义) | 跨平台、无服务器依赖 |
| Python 绑定 | PyO3 + maturin | Rust 生态标准方案 |
| WASM | wasm-bindgen | 浏览器原生支持 |
